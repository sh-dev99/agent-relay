# エージェント間でメッセージを送る

ユーザーが指定したチャットに、依頼、報告、返事などの文章を届ける。資料が必要なら、宛先から読めるファイルのパスを本文に添える。

使い捨ての子に一度だけ作業を任せる場合は、利用環境のエージェント分担機能を使う。

## 宛先を決める

指定されたチャットか、この依頼で新しく作ったチャットを使う。名前から探す場合も送信には確定した ID を使い、報告に名前と ID を添える。同名の候補が複数ある場合は、送る前にどのチャットかを確かめる。

相手が返答中でも、通常の送信は宛先別の手順に従う。「今の作業に反映して」などの指定があれば、相手がその返答を終える前に読める方法を選ぶ。ユーザー入力と同じ吹き出し、公式経路、画面を切り替えないことなどが指定されていれば、その条件も満たす経路を選ぶ。条件に合う経路が確認できない場合は送信を見合わせる。

## 宛先別の手順

| 宛先 | 通常の送り方 |
| --- | --- |
| [Codex](references/codex.md) | この端末のチャットには公式キュー（受信待ちの一覧）へ送る。特定のターンへの追記や別ホスト（durable）宛ては個別手順へ。 |
| [Claude Code](references/claude.md) | Claude Code 同士なら `SendMessage`、他のアプリからは `claude_send.py`。返答中に届くかは、送り方と相手の状態による。 |
| [Antigravity](references/antigravity.md) | アプリで開いた会話には `agy_send.py send`。待機中は新しい返事が始まり、作業中は次のモデル呼び出しで取り込まれた例がある。アプリと CLI の会話は別の宛先。 |
| [OpenCode](references/opencode.md) | `opencode_send.py` で既存セッションへ送る。待機中の受信と返答は確認済みで、作業中の取り込み時点は未確認。 |
| [Cursor](references/other-apps.md#cursor) | Desktop の会話から他のアプリへ送れる。CLI の会話には追記できる。Desktop の既存会話への受信は未確認。 |
| [Grok Bot](references/other-apps.md#grok-botxai) | Webhook で用意済みの Routine を起動し、その会話か指定した返信先で結果を確かめる。 |
| [Muse・Muse Code・dots](references/other-apps.md#muse) | Muse のメイン会話には別途ブリッジが必要。Muse Code と dots の対応は個別手順を確認する。 |

送信コマンドの例はスキルフォルダを起点に実行する。ローカル Codex への通常送信では、送信元を問わず次の形を使う。

```bash
python3 scripts/codex_send.py --thread "$thread_id" --host-id local \
  --sender "$sender_name" --message-id "$message_id" < "$body_file"
```

アプリによっては、ウィンドウを閉じた後もアプリが動いているか、宛先のチャットを開いているかで、届くタイミングが変わる。事前に確認すべき条件や、自動でチャットを開くかどうかは宛先別の手順を参照する。[時刻を指定して送る](references/delivery.md#時刻を指定して送る)

## 送信後に確かめる

キューに載った時点で確認できるのは受付まで。宛先の会話記録や画面の本文にメッセージが現れたら「到達」とする。読了は返信や入力に沿った処理で確かめる。同じターンへの到達が条件なら、メッセージ ID とターン ID を照合し、ターン終了前の反応を確認する。ユーザー入力と同じ表示が必要なら、画面の吹き出しまで見る。

受付だけを確認できた場合は「受付済み・到達未確認」と伝える。送信後の通信断などで結果が分からない場合は、再送や経路変更の前にキューと宛先の記録を確かめる。[到達確認と再送の手順](references/delivery.md)

## 本文と返信先

送り主と用件が分かるように書く。`--sender` で送り主が自動的に付く経路では、本文に重ねて書く必要はない。返信がほしいときは返信先のアプリとチャット ID を明記する。鍵やパスワードは本文や引数に含めない。

```text
<送り主の名前とID>から　<件名>
返信先　<使う経路と宛先ID>
やること　<作業・範囲・完了条件>
完了したら「DONE」と結果を、作業を続けられない場合は「BLOCKED」とその理由を返信する。
```

受け取った AI は送り主を確認し、権限が必要な操作は受信側の承認手順に従う。完了報告へのお礼だけの返信は省く。
